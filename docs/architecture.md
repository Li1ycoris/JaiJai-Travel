# 分類與編號決策

採用目的地 → 區域 → 分類三層操作。目的地範例為花蓮、曼谷；不加國家。區域先平鋪，不使用無限多層樹。景點不是區域的替代欄位：大型園區仍為景點，活動以 parentId 關聯。

| 編號方案 | 例子 | 優點 | 代價 |
|---|---|---|---|
| 區域＋類型固定序號（採用） | CT-P1、CT-A1、CT-F1 | 可辨位置與類型，適合地圖 | 跨區列表較長；單區可縮寫 |
| 全目的地固定序號 | P1、A1、F1 | 字短且好記 | 無法從號碼看區域 |
| 名稱為主、無編號 | 花蓮文創園區 | 無記號學習成本 | 地圖標記佔空間，無簡短索引 |

P=Place、A=Activity、F=Food、S=Stay、T=Transport。活動編號不嵌景點號（例如P1-A1），避免搬場或更換所屬景點時連動改號。真正關聯永遠使用記錄ID。

花蓮六區：CT市中心與南濱、ST花蓮車站周邊、ML美崙與花蓮港、QT七星潭周邊、XC新城與北郊、SF壽豐海岸。這是可調整的編輯分區，不是行政界線。區域移轉需明確檢查新區號碼，保留記錄ID。

選單用左上漢堡按鈕打開可關閉側欄（原生dialog，支援焦點限制與Escape）；頂欄黏住。侧欄只選目的地，主畫面選區域和分類，避免側欄太深。區域與分類交集為空時顯示空狀態；曼谷準備中不顯示花蓮天氣、照片或資料。

資料採分類檔＋areaId索引，而非把每一區整棵複製一遍。建置輸出統一前端資料包。目前規模適合靜態資料包；資料增多時可把相同目的地模型分包載入而不變更資料關聯。
